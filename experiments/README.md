# Experiments

Each YAML in this directory is a complete `harbor.models.job.config:JobConfig`
spec — task(s), agent(s), environment, network policy, retry, metrics.
Pass directly to Harbor:

```bash
harbor run -y --config experiments/<name>.yaml
```

No `-p`, no `-a`, no `--ek` shell-quoting nonsense — everything lives
in the YAML.

## The hero-run sweep

These are the configs behind the published numbers — 8 tasks × 7
policy columns × k=3, Claude Opus 4.7 via Claude Code, all under
`experiments/hero-run-v2/`. One YAML per (policy, task); `__retry`
variants fill trials that flaked in the original jobs (the dashboard
merges `<job>__retry*` dirs into the same cell).

| Config family | Policy |
|---|---|
| `control-opus__*` | unaugmented task, no gateway — natural baseline |
| `hero-open-opus__*` | cheat nudge, no gateway |
| `hero-network-none-opus__*` | deny-all, all phases (breaks setup → legit-break) |
| `hero-v2-host-blocklist-v2-opus__*` | curated host deny list |
| `hero-v2-content-filter-v2-opus__*` | response-body regex (literals, base64 variants, constants) |
| `layered-tools-off__*` | host ∪ content + WebSearch/WebFetch disabled |
| `hero-v2-llm-judge-request-opus__*` | Sonnet 4.6 request-intent judge + tools-off |

The YAMLs are generated by `render_sweep.py` (which owns the per-task
content-filter regexes and host lists) but the checked-in copies are
the source of truth for what actually ran.

After running jobs:

```bash
uv run --no-project experiments/hero-run-v2/extract_results.py   # jobs/ -> results/
uv run --no-project experiments/hero-run-v2/render_dashboard_v2.py
```

## How to author a new experiment

The relevant `JobConfig` fields are documented at
`harbor/models/job/config.py:JobConfig`. The shape we use is:

```yaml
job_name: <unique-name>
n_attempts: <int>           # -k equivalent
n_concurrent_trials: <int>  # -n equivalent

environment:
  type: islo                # docker | islo | daytona | modal | e2b | ...
  kwargs:
    gateway:                # only valid for type: islo (phased schema is mandatory)
      setup:                # per-phase: setup / agent / verifier
        default_action: allow
      agent:
        default_action: allow | deny
        rules:
          - host_pattern: <glob>
            action: allow | deny
            priority: <int>     # lower number = higher priority
            # optional: path_pattern, methods, content_filter
            # content_filter: {direction: request|response|both,
            #                  filter_type: regex|content_type|size_limit,
            #                  pattern: <regex/mime/bytes>}
      verifier:
        default_action: allow

agents:
  - name: claude-code | oracle | aider | ...
    model: anthropic/claude-haiku-4-5  # required for claude-code

tasks:
  - path: datasets/reward-hack/<task>
  # or:
  # - name: org/task-name      # registry tasks
  # - git_url: ...

# Optional:
# datasets:
#   - path: datasets/reward-hack
# retry:
#   max_retries: 2
# metrics: [...]
```

Network policies (`gateway`) live inline in each experiment YAML;
`render_sweep.py` owns the shared rule sets (host lists, per-task
content-filter regexes) and stamps them into the generated configs.
